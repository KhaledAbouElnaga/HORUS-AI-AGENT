# M5 Latency Benchmark

## Real local integrated measurements

Source: `artifacts/m5_sustained_local.json`, generated by `PYTHONPATH=src python scripts/run_m5_sustained_local.py`.

| Metric | p95 | State |
|---|---:|---|
| transcript-final → HORUS full response ready | 21.027 ms | PASS |
| HORUS response ready → first Piper audio | 213.577 ms | PASS |
| user-end → first response audio | 3,553.642 ms | PASS |
| cancellation → downstream silence | NOT MEASURED | native mid-response cancellation unavailable; stale-audio count 0 |
| spoken tool intent → real tool result | 11.46 ms | PASS |
| memory lookup latency / update latency | 1.005 / 0.693 ms | PASS |
| RSS start → end / drift | 502.98 → 732.59 MB / +229.61 MB | PASS |

Native HORUS first-token latency is **NOT MEASURED**. The local agent returns a completed response; the adapter records `runtime_response_ready_ms` rather than relabelling it as first-token latency.

## M4 comparison

M4's full-pipeline evidence used a different local streaming path and reported first-token p95 1,332.59 → 1,402.96 ms with RSS growth 451.69 MB. The M5 command-only local path is not directly comparable in model work; the difference and the missing native-stream metric remain visible rather than treated as a win.
